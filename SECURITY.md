# Security Policy

## Supported Versions

Security fixes are released for the latest minor version of each crate:

| Crate         | Supported            |
|---------------|----------------------|
| `tideway`     | latest 0.x release   |
| `tideway-cli` | latest release       |

Older versions do not receive backported fixes. Upgrade to the latest release to pick them up.

Code generated by `tideway-cli` is owned by your application once generated. When a release fixes
a generated template, the [CHANGELOG](CHANGELOG.md) describes the change so existing apps can apply
it by hand; see [docs/upgrading.md](docs/upgrading.md).

## Reporting a Vulnerability

Please do not open a public issue, discussion, or pull request for a suspected vulnerability.

Report it privately through GitHub instead:
[Report a vulnerability](https://github.com/jordcodes/tideway-rs/security/advisories/new)
(the **Security** tab → **Report a vulnerability**).

Include as much of the following as you can:

- the affected crate and version (or commit)
- the component or generated template involved
- the security impact, and the conditions an attacker needs
- steps to reproduce, ideally against a minimal local app

You can expect an acknowledgement within a few days. Once the report is confirmed, a fix is
prepared privately and released, and the issue is then published as a GitHub Security Advisory.
Reporters are credited in the advisory unless they prefer otherwise.

## Scope

In scope:

- the `tideway`, `tideway-cli`, and `tideway-macros` crates
- code and configuration generated by `tideway-cli` templates

Out of scope:

- vulnerabilities in third-party dependencies (report those upstream; we will update once a fix
  is available)
- issues that require a misconfiguration the documentation warns against, such as production
  deployments that use the development secrets created by `tideway dev --fix-env`
